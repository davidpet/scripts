# Status

This Premiere Pro plugin is meant to help with clip operations. It is not yet working.  I went back and forth with ChatGPT to nail down the spec, but it's turning out the API is weirder than expected and is having a lot of issues. The code is primarily generated, edited, and re-generated by ChatGPT for the sake of saving time, since I intended to use the plugin for my own video editing and not to release it.

# Installation

This plugin is just a normal one - you can point to the manifest.  Nothing to build.

# Intended Features
1. A panel to dump out all effect properties (built-in and standard) on selected clip. This was motivated by the observation that Premiere Pro rounds float values in the UI, and also truncates UI input to 7 characters even though internally it can represent more precision.  For instance, if you want to copy scale from Motion to Transform, you can only get it rounded to 1 decimal place, but internally, if you set it with Fit or Fill, it may have many more digits than that.
1. A panel to nudge the anchor point without visually moving the layer (update anchor point and position properties together).
1. A headless command to extract Motion properties into a new Transform effect and reset Motion properties to default. This is to aid in adding camera moves to a clip which requires manually extracting like this (in order to get access to shutter angle).
1. A headless command to collapse adjacent transform effects in the chain into a single transform effect (eg. if have 2 scales and nothing in between, combine for a higher-quality resample).

# Issues

1. Only the `Dump Effects` panel has been tested at all - the status of the other 3 thngs is not yet known. All following issues in this list are for `Dump Effects` panel.
1. The API returns coordinates inconsistently - it's always normalized in the range [0-1] rather than pixel coordinates (even though the Premier Pro UI takes pixel coordiantes) - so the intent is that it will display pixel coordinates after calculating. But different clip types represent it in different ways, and not all have been fixed yet.
1. When pixel coordinates are shown, because we had to convert from float, there is sometimes some rounding error (eg. UI shows 639, but API returns something like 638.9999900004).
1. The text area is not showing a scrollbar when the content exceeds the size of the text area.
1. The panel sizing is very stubborn - it does not resize and does not start up at the specified size.  The UI looks terrible when the panel is too small.
1. It needs a way to copy float values as rounded to 7 ascii characters for input into Pr panels (maybe with a 3 option dropdown for round up, round down, round nearest).

# Conclusion

After going through multiple rounds with ChatGPT and the API spec, I've decided to stick with manual methods for now. I might try smaller one-off plugins to assist in parts of the workflow, but I'll try manual for a while so I can think more about what I actually need instead of these grand theoretically awesome utilities.

One thing I learned from dealing with `Dump Effects` is that the API doesn't quite match the UI, and doesn't quite match between clip types, which makes UXP plugins more annoying than I thought at first. Finding this out is what seriously de-motivated me to continue refining.

Here are some additional pitfalls of using an LLM to vibe code this:

1. Don't give it too much context - I tried to do the whole plugin with all 4 commands at once, and I think that diluted the context too much.
1. Before you accept the code, check for dumb mistakes like these (which it made):
  i. Using `import` instead of `require` for UXP (unless you are using a node build, which this wasn't).
  i. Not using `await` on all calls of async helpers, even ones it created.
  i. Getting paths wrong (may be due to dilusion of context that I mentioned)
